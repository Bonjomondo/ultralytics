# 新旧作者引擎实验的代码与执行协议核查

核查范围为旧350轮C2/Scalar及新150轮C2/Scalar。主要训练数学与超参数一致，初始化、数据加载并发、恢复轨迹及checkpoint存储精度存在明确差异。seed0不能代表跨批次使用了相同初始权重。原先用“同一作者引擎和配方”概括两批实验，未充分突出初始化协议变更。

## 代码、结构与超参数

旧C2源码清单139项、旧Scalar清单153项、新冻结源码151项，当前逐项哈希均匹配各自记录。对比Python后端，旧C2与新后端共有文件仅nn/tasks.py有差异，改动是注册P2GateConcat。旧Scalar与新后端共有文件也仅nn/tasks.py有差异，涉及ScalarP2Concat与P2GateConcat的注册及Concat通道统计。损失、RT-DETR trainer、数据增强、DataLoader、优化器实现等共有文件逐字节相同。

C2模型YAML解析后的结构完全相同。Scalar只将原ScalarP2Concat改为通用P2GateConcat的scalar模式，均作用于128通道P2分支，倍率2*sigmoid(logit)、初值1。旧参数为零维标量，新参数形状为[1]，均为1个参数。使用固定CPU输入、logit=-0.7/0/0.7进行检查，新旧输出、所有输入梯度、门控梯度及一步AdamW更新均逐元素相同。此测试覆盖门控算子，不宣称两次完整训练逐位一致。

实际args.yaml对比，数学相关差异为epochs350→150、patience40→0、workers8→0。其余差异为输出、配置路径和名称。以下相同：640、batch4、nbs4、accumulate1、AdamW、lr0=1e-4、lrf=1、weight_decay1e-4、warmup2000 batch、mosaic1、mixup0.2、close_mosaic0、FP32训练、seed0、无预训练。350轮实验实际完成全部350轮，因此早停差异不能解释前150轮排序。lrf=1使warmup后的调度恒定，epochs差异没有把前150轮改成不同的学习率衰减阶段。

旧data.yaml和新data.yaml的根路径不同，但当前解析到同一训练/验证图片与标签目录，四个目录samefile均为True。现有核查未发现数据源切换。此目录核对不能替代未记录的历史全量图片字节快照。

## 已直接验证的初始化差异

旧方法先构建候选C2/Scalar，再重放B0随机初始化，将527项同名同形状态复制到候选，P2分支保留候选构造值。新方法先构建完整C2初始化，再将全部533项状态复制到C2/Scalar/Channel。

在CPU重放旧Scalar初始化后，用旧算法计算527项共有状态的哈希，得到cd1cf17318a869866d8bdf80e67e76a16828c783e8361c23b82c1e579ce3a7c0，与旧训练归档receipt完全匹配。对新保存的initialization_s0.pt使用相同键集和相同算法，得到647a453a6d1126600b13d40d19d0bfd4c4e0eafd5194cf1108f668eee664e115。

527项中444项相同，83项不同。差异集中在model.19/20/22/23/25/26，即后续融合层与Decoder，包括随机初始化的卷积、注意力和预测头权重。不同项清单完整保存于[审计JSON](code_protocol_audit.json)。旧完整初始模型未保存，但这527项有原训练哈希作验证。P2分支的重放值与新初始化一致，仅此部分受旧完整初态缺失限制。

初始化过程对训练随机流的消耗也不同。旧代码在外部构建候选，再在fork_rng中重放B0。新paired()在fork_rng中构建C2与候选并复制完整状态。相同seed不能保证跨这两个构造流程的后续Torch随机流一致。

## 并发、恢复及权重精度

| 项目 | 旧350轮 | 新150轮 |
|---|---|---|
| C2训练workers | 8 | 0 |
| Scalar训练workers | 前130轮8，之后0 | 0 |
| 恢复记录 | Scalar从完整130轮状态恢复 | C2从完整50轮及98轮状态恢复 |
| 模型/EMA/优化器恢复 | 旧Scalar逐项校验通过 | 新C2逐项校验通过 |
| 旧/新C2最佳权重存储浮点类型 | FP16 | FP32 |
| Scalar最佳权重存储浮点类型 | FP32 | FP32 |

DataLoader worker改变会改变增强随机流，恢复也可能改变采样与增强次序。新C2第一次在第51轮失败，因此第50轮以前的跨批次差异不能归因于这次恢复。旧前150轮Scalar已经落后C2，新前150轮排序反转，初始化与workers在训练开始时就已不同。

旧C2 best.pt为242571980字节，存储浮点张量为FP16。旧Scalar best.pt为323198405字节，浮点张量为FP32。训练时amp=false与权重落盘精度是两个维度。评估时转回FP32不能恢复FP16量化前的数值。因此旧最终正式AP比较还包含存储精度差异。训练过程中记录的前150轮原生mAP在保存量化前产生，该差异解释不了其排序。

## 可以得出的结论

确认存在初始化权重与执行协议差异，不能把排序反转只归因于轮数或直接当作同条件重复结果。没有发现主要损失、数据增强、有效batch、优化器或Scalar算子数学发生变化。

初始化差异、worker随机流、恢复轨迹均为已核实的混杂因素。现有比较没有一次只改变一个因素，因此无法分配各因素造成的AP变化，也无法证明83项初态差异就是排序反转的唯一原因。下一次受控验证应固定一份完整初始状态，并显式固定模型构造后训练随机状态、加载器生成器及workers，再单独改变待测因素。当前仅做核查，未启动训练。
